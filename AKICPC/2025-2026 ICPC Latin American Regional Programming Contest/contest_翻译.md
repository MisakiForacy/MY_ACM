## 问题 A – 苹果派（Apple Pie）

**作者：Alejandro Strejilevich de Loma（阿根廷）**

Asdrubal 喜欢写整数序列，也喜欢吃苹果派，有时他两件事同时做。最近他对一种特殊类型的序列产生了兴趣。给定一个整数 N ≥ 2，他想找到一个序列，使得 1 到 N 之间每一对不同整数组成的集合，都恰好一次出现在序列的相邻位置上。此外，序列中不能出现其他整数。

例如，当 N = 2 时，1 到 N 之间只有一对不同的整数，即集合 {1, 2}。因此 Asdrubal 会接受序列 [1, 2]；另一种可能是序列 [2, 1]。

当 N = 3 时，1 到 N 之间有三对不同整数的集合：{1,2}、{1,3} 和 {2,3}。此时序列 [2,1,3,2] 是合法的：集合 {1,2} 只出现在前两个位置，集合 {1,3} 只出现在中间两个位置，集合 {2,3} 只出现在最后两个位置，且序列中没有出现其他整数。另一方面，序列 [2,1,3]、[2,1,3,2,1] 和 [2,1,3,2,2] 都是不合法的。

Asdrubal 认为他刚刚为某个 N 写出了他的一个序列。他正要检查这个序列是否真的合法，这时一些苹果派掉到了纸上。苹果派盖住了序列中的零个或多个元素，把其余部分分成了左右两个（可能为空的）部分。

给定苹果派左右两侧未被盖住的序列片段，你必须判断原始的完整序列**是否可能是合法的**。

> 注：合法序列的长度恰好为 C(N,2)+1 = N(N−1)/2 + 1（每条边恰好作为相邻对出现一次），即图论中的"欧拉迹"：把 1..N 看作顶点、每对无序顶点看作一条无向边，序列对应完全图 K_N 的一条欧拉路径。

### 输入
第一行包含一个整数 **N**（2 ≤ N ≤ 1000）。

第二行包含一个整数 **P**（0 ≤ P ≤ 5×10⁵），表示苹果派左侧的整数个数，随后是这 P 个整数 L₁, L₂, ..., L_P（1 ≤ L_i ≤ N）。

第三行包含一个整数 **Q**（0 ≤ Q ≤ 5×10⁵），表示苹果派右侧的整数个数，随后是这 Q 个整数 R₁, R₂, ..., R_Q（1 ≤ R_i ≤ N）。

左右两个片段都按从左到右的顺序给出。

### 输出
输出一行大写字母 "Y"（如果原始完整序列可能是合法的）或 "N"（否则）。

**样例 1**

输入：
```
2
0
0
```
输出：
```
Y
```
解释：N = 2，苹果派盖住了整个序列（P = Q = 0）。由于 N = 2 至少存在一个合法序列（例如 [1,2]），Asdrubal 写的序列可能是合法的。

**样例 2**

输入：
```
3
1 2
0
```
输出：
```
Y
```
解释：N = 3，苹果派盖住了除第一个元素之外的所有内容（P = 1，Q = 0）。由于 N = 3 至少存在一个以 L₁ = 2 开头的合法序列（例如 [2,1,3,2]），所以原序列可能是合法的。

**样例 3**

输入：
```
3
2 2 1
2 3 2
```
输出：
```
Y
```
解释：又是 N = 3，但这次苹果派盖住了序列中间的零个或多个元素。由于 N = 3 至少存在一个以 [2,1,…] 开头、中间有零个或多个元素、最后以 […,3,2] 结尾的合法序列（同样是 [2,1,3,2]），所以原序列可能是合法的。

**样例 4**

输入：
```
3
2 2 1
1 3
```
输出：
```
N
```

**样例 5**

输入：
```
3
2 2 1
2 2 1
```
输出：
```
N
```

**样例 6**

输入：
```
3
2 2 1
2 2 2
```
输出：
```
N
```

## 问题 B – 平衡气球（Balanced Balloons）

**作者：Marcos Kolodny（阿根廷）**

一群学生正在组建一个竞赛编程社团，他们预计会有 N 个人陆续加入。每个人加入时，必须带来 1 到 K 个气球。

创始人们希望确保公平，并决定实施以下公平规则：每加入一个人之后，必须可以把目前收集到的所有气球平均分配给当前成员。换句话说，每一步之后，气球总数必须能被当前人数整除。

作为竞赛程序员，他们意识到这是一个不错的计数问题，于是决定向你发起挑战：有多少个长度为 N 的气球贡献序列（每次贡献在 1 到 K 之间）满足每一步的公平规则？

如果两个序列在任一位置上不同，就认为它们是不同的。

### 输入
输入为一行，包含两个整数 **N**（1 ≤ N ≤ 10⁹）和 **K**（1 ≤ K ≤ 2000），分别表示成员人数和每人最多可带来的气球数。

### 输出
输出一行整数，表示满足公平规则的气球贡献序列的数量。由于这个数可能非常大，输出它对 **998244353** 取模的结果。

**样例 1**

输入：`3 3`　输出：`5`

解释：5 个合法序列为：[1,1,1]、[1,3,2]、[2,2,2]、[3,1,2]、[3,3,3]。

**样例 2**

输入：`4 1`　输出：`1`

解释：每个人都必须贡献恰好 1 个气球，所以唯一可能的序列是 [1,1,1,1]。

## 问题 C – 清洁街道（Clean Streets）

**作者：Roberto Sales（巴西）**

圣保罗的"文化之夜"（Virada Cultural）又到了一年一度的时候。城市里挤满了人，街道充满活力。来自全市各地的人们走上街头，享受这一夜的文化活动和大量音乐。

Oswaldo 是市政府的一名职员，他被分配了在此次活动结束后 **不超过 K 小时** 内雇佣清洁工打扫 S 条街道的任务。他的老板给了他一份可供雇佣的 N 名清洁工名单，编号从 1 到 N，以及他们各自的工作速度和可接受的报酬信息。根据名单，清洁工 i 打扫任意一条街道需要 H_i 小时，每打扫一条街道可接受的报酬在 L_i 到 U_i 之间的任何值。

Oswaldo 必须雇佣名单中的一个子集 C 的清洁工。对于每名被雇佣的清洁工 i ∈ C，他必须分配 s_i 条街道（每人的街道数为正整数），并指定每街道的报酬 p_i，同时遵守以下准则：

- 每个 s_i 必须是正整数，且 Σ_{i∈C} s_i 恰好等于 S，因为每条街道都必须被打扫，且没有街道能由多于一名清洁工打扫。
- 每名被雇佣的清洁工 i 需要 s_i · H_i 小时来打扫分配的街道。由于清洁工可以并行工作，整个清洁工作总共需要 max_{i∈C}(s_i · H_i) 小时完成。这个总时间必须**至多为 K 小时**。
- 每街道报酬 p_i 必须是 L_i 与 U_i 之间的有理数（即 L_i ≤ p_i ≤ U_i）。
- 为保证招聘过程公平，每小时报酬 p_i / H_i 对所有被雇佣的清洁工必须**相同**。

注意：以上限制不适用于未被雇佣的清洁工。

被雇佣的清洁工 i 将获得 s_i · p_i 的报酬，总报酬为 Σ_{i∈C} s_i · p_i。帮助 Oswaldo 确定符合上述准则的**最小总报酬**；如果无法满足这些要求，则告诉他无法满足。

### 输入
第一行包含三个整数 **N、S、K**（1 ≤ N, S ≤ 10³，1 ≤ K ≤ 10⁹），分别表示可用清洁工数量、需要打扫的街道数量，以及完成工作的时限小时数。每名清洁工用 1 到 N 之间的一个不同整数标识。

接下来的 N 行中，第 i 行用三个整数 **H_i、L_i、U_i**（1 ≤ H_i ≤ 10⁵，1 ≤ L_i ≤ U_i ≤ 100）描述清洁工 i：表示该清洁工打扫任意一条街道需要 H_i 小时，每街道报酬接受 [L_i, U_i] 范围内的任何值。

### 输出
如果准则可以满足，输出一行两个正整数 x 和 y，使得 x/y 是表示最小总报酬的最简分数。如果无法满足这些要求，输出一行字符 "*"（星号）。

**样例 1**

输入：
```
2 15 10
1 4 10
1 4 10
```
输出：`801 228`

**样例 2**

输入：
```
2 7 9
3 4 10
3 4 10
```
输出：`683 228`

**样例 3**

输入：
```
2 15 10
1 4 10
5 2 8
```
输出：`*`

## 问题 D – 显示小数（Displaying Decimals）

**作者：Bruno Monteiro（巴西）**

在金砖国家推出国际共同支付货币（ICPC）之后，所有货币（如雷亚尔、比索、美元等）都由它们各自的 ICPC 价值来定义。

为了帮助人们在这个新秩序中导航，你决定创建一个网站来计算货币之间的汇率。网站处理 N 种货币，编号从 1 到 N。每种货币 i 有一个关联的整数值 A_i，表示 1 单位货币 i 价值 A_i 个 ICPC。

网站的工作方式如下：用户先选择一种源货币 i，然后选择一种目标货币 j（j 可以等于 i），网站会显示它们之间的汇率，即 A_i / A_j 的**精确十进制表示**。

为了处理循环小数，你决定只显示第一个循环节（存在时用其上方的横线表示）。因此：
- 4/4 = 1 需要显示 1 位数字；
- 4/3 = 1.333…（即 1.3̄）需要 2 位数字；
- 41/4 = 10.25 需要 4 位数字；
- 3/14 = 0.2142857142857…（即 0.2̄142857）需要 8 位数字。

你的网站已成功运行了很长时间。作为性能分析的一部分，你想计算汇率显示页面的期望显示大小。

给定 A_1, A_2, ..., A_N，当 i 和 j 在 1 到 N 之间均匀随机选取时，计算显示 A_i / A_j 所需位数的**期望值**。

### 输入
第一行包含整数 **N**（1 ≤ N ≤ 10⁵），表示货币数量。

第二行包含 N 个整数 A_1, A_2, ..., A_N（1 ≤ A_i ≤ 10⁵），其中 A_i 是 1 单位货币 i 以 ICPC 表示的价值。

### 输出
所求期望值可表示为最简分数 P/Q，其中 Q 与 M = 998244353 互质。令 Q⁻¹ 为 Q 模 M 的乘法逆元，即 Q · Q⁻¹ ≡ 1 (mod M)。输出一行整数 **P · Q⁻¹ mod M**。

**样例 1**

输入：
```
3
15 36 14
```
输出：`332748121`

解释：下表显示各商（行/列）所需的位数，每个的概率为 1/9。

|     | 15 | 36 | 14 |
|-----|----|----|----|
| 15  | 1  | 4  | 8  |
| 36  | 2  | 1  | 7  |
| 14  | 3  | 3  | 1  |

例如，14/36 = 0.3888…（即 0.3̄8）需要 3 位数字。期望位数为 30/9 = 10/3，即 P = 10，Q = 3。由于 Q⁻¹ = 332748118，最终输出为 10 · 332748118 mod 998244353 = 332748121。

## 问题 E – 应急口粮（Emergency Rations）

**作者：Andr é Amaral de Sousa（巴西）**

一个村庄储存着应急口粮箱。每个箱子装有若干口粮，村长会记录每个箱子里有多少口粮。最初，储备中没有任何箱子。有时会向储备中添加一个新箱子，或者移除一个已有箱子。

在紧急情况下，村民必须在紧急情况持续的每一天**恰好选择以下两种行动之一**：
1. 挑选一个非空箱子，用掉该箱子里的所有口粮；或
2. 从每个非空箱子中用掉 1 份口粮。

村长担心口粮被过快消耗。因此，每次储备发生变化后，村长想知道：假设发生紧急情况且村民选择能让所有箱子变空的最优行动，需要多少天才能把所有箱子清空。

注意：口粮实际上并不会被用掉；村长只想知道清空所有箱子所需的最少天数。由于村长无法独自完成这些模拟计算，你被请求提供帮助。

### 输入
第一行包含整数 **Q**（1 ≤ Q ≤ 3×10⁵），表示储备的变化次数。

第二行包含 Q 个带符号整数 X_1, X_2, ..., X_Q（1 ≤ |X_i| ≤ 10⁹），按时间顺序表示储备中箱子的添加和移除。正值 X_i = +c 表示添加一个装有 c 份口粮的箱子；负值 X_i = −c 表示移除一个恰好装有 c 份口粮的箱子。

保证每次移除都是合法的，即每当移除 X_i = −c 发生时，储备中至少有一个恰好装有 c 份口粮的箱子。

### 输出
输出一行 Q 个整数，第 i 个整数表示第 i 次变化之后清空所有口粮所需的最少天数。

**样例 1**

输入：`8` 然后 `+1 +2 +2 +7 -2 +10 -1 -2`　输出：`1 2 2 3 3 4 3 2`

**样例 2**

输入：`2` 然后 `+42 -42`　输出：`1 0`

## 问题 F – 模糊分解（Fuzzy Factorization）

**作者：Luis Santiago Re（阿根廷）**

对大数进行质因数分解是一项具有挑战性的任务。它非常困难，以至于从网银到私人信息，我们整个数字世界的安全性几乎都建立在它的难度之上。在本题中，你需要进行这样的分解，但答案允许一定的**相对误差**。

更正式地说，给定一个整数 X，你需要给出任意一个数 Y = p₁^e₁ · p₂^e₂ ··· p_k^e_k 的质因数分解，使得：
- 该分解的相对误差不超过 10⁻⁹（即 |X − Y| / X ≤ 10⁻⁹）；
- Y 的每个质因数 p_i 不超过 10¹⁸（即 p_i ≤ 10¹⁸，i = 1, 2, ..., k）。

### 输入
输入为一行，包含整数 **X**（2 ≤ X ≤ 10¹⁰⁰⁰）。

### 输出
第一行必须包含正整数 k，表示 Y = p₁^e₁ · p₂^e₂ ··· p_k^e_k 的质因数分解中不同质因数的个数。

接下来的 k 行中，第 i 行包含两个正整数 p_i 和 e_i，表示 p_i 是 Y 的质因数，重数为 e_i。

可以证明在给定约束下存在合法答案。如果有多个解，输出任意一个。

**样例 1**

输入：`520`　输出：
```
3
5 1
2 3
13 1
```
（即 Y = 5 · 2³ · 13 = 520。）

**样例 2**

输入：`1073741825`　输出：
```
1
2 30
```
解释：X = 1073741825，Y = 2³⁰ = 1073741824，相对误差为 |X − Y| / X = 1/1073741825 ≤ 10⁻⁹。注意此测试用例还有其他合法解。

## 问题 G – Gridoland 电力计量（Gridoland Power Gauge）

**作者：Gabriel Poesia（巴西）**

Gridoland 是一座由 N × M 个街区组成的城市，其电网设计得非常健壮。城市的电力来源是一座大坝，它可以产生任意大的电流，并连接到左上角的街区，坐标为 (1,1)。市长计划在市政厅（坐标 (N,M)）举办一场耗能巨大的庆典，她雇你帮助规划委员会。

Gridoland 的每个街区都有自己的电力变压器。每个变压器有一个初始电流通过容量，但容量随时间线性变化，每个变压器的速率可能不同。技术人员已测定每个变压器的初始容量 C_ij 和变化速率 R_ij（可正、可负、可为零）。因此你知道街区 (i,j) 的变压器在第 t 分钟的容量为 C_ij + t · R_ij。

电流借助若干电缆在城市中流动。Gridoland 的所有电缆均由超导材料制成，可以沿任一方向通过任意大的电流。市长亲自把城市的连通图交给了你，其中包含所有由（垂直或水平方向）相邻且由电缆连接的街区对。

庆典期间，除市政厅外所有街区都没有能源消耗，因此进入电网的所有电流都将用于庆典。庆典必须在未来**至多 K 分钟**内举行，因为市长的任期将在那时结束。你必须回答规划委员会的以下问题：在 [0, K] 范围内整数分钟 t 时刻，电网供给庆典的峰值容量是多少？

在每个时刻，从市政厅的角度看，电网容量等于能从电源流向市政厅的最大电流量。每个变压器进入的电流受其容量限制，并受"进入一个街区的所有电流必须全部流出"的约束（市政厅除外——庆典期间它会消耗其收到的所有能量）。

### 输入
第一行包含四个整数 **N、M、P、K**（2 ≤ N, M ≤ 300，P ≥ 0，0 ≤ K ≤ 10¹²）。N 和 M 表示城市尺寸，P 表示连通图中的电缆数量，K 是市长任期剩余分钟数。

接下来的 N 行，每行 M 个整数。第 i 行第 j 个整数是 C_ij，即街区 (i,j) 变压器的初始容量（0 ≤ C_ij ≤ 10¹²）。

再接下来的 N 行，每行 M 个整数。第 i 行第 j 个整数是 R_ij，即街区 (i,j) 变压器的变化速率（−10⁶ ≤ R_ij ≤ 10⁶）。

## 问题 H – 更艰难的视野（Harder Horizons）

**作者：Paulo Cezar Pereira Costa（巴西）**

Lola 有一份长长的待办任务清单，她需要按任务出现的顺序完成它们。每个任务有一个难度数值（数值越大，任务越难）。

清单不断增长，因为任务很少被移除。对此感到厌倦的 Lola 决定采取行动：她想把清单分成若干个连续的任务组，每组代表她一天要完成的工作。

为了保持动力，Lola 希望感觉到每天都在进步。因此，从第二天开始，当天的最难任务必须**严格难于**前一天的最难任务。

Lola 也不想在一天内做太多事，所以她希望把工作分散到尽可能多的天数中。

在这些规则下，她最多能把任务分成多少天？

### 输入
第一行包含整数 **N**（1 ≤ N ≤ 10⁵），表示任务数量。

第二行包含 N 个整数 D₁, D₂, ..., D_N（1 ≤ D_i ≤ 10⁵），表示清单中按顺序排列的任务难度。

### 输出

解释：分成 4 天的一种最优方案是：1 | 2 | 1 | 3 | 4（后四组每天的最难任务为 1、2、3、4，严格递增）。

解释：分成 3 天的一种最优方案是：2 | 4 | 2 3 5，每天最难任务为 2 < 4 < 5。

## 问题 L – 孤独的生物（Lonely Creatures）

**作者：Paulo Cezar Pereira Costa（巴西）**

城市刚刚建了一个新的游乐场。游乐场的边界是（坐标轴对齐的）抛物线 y = A · x² + B，其中 A > 0。游乐场是开区域 y > A · x² + B，因此恰好在边界上的点不算在游乐场内部。

现在市政官员想知道新游乐场是否减少了孤独，这正是需要你的地方。你的任务是统计有多少对不同的生物，它们的相遇点**严格位于游乐场内部**。每对只统计一次；对中生物的顺序不重要。

### 输入
第一行包含三个整数 **N**（2 ≤ N ≤ 10⁵）、**A**（1 ≤ A ≤ 10⁴）和 **B**（−10⁴ ≤ B ≤ 10⁴），表示有 N 个生物，游乐场是平面上的开区域 y > A · x² + B。每个生物用 1 到 N 之间的一个不同整数标识。

2 0
```
输出：`0`

解释：生物 1 与生物 2、生物 3 都相遇，但两次相遇点都在游乐场之外。没有其他相遇点，所以答案为 0。

**样例 2**

1 0
2 1
```
输出：`3`

解释：每对生物都有相遇点。但生物 3 与生物 4 的相遇点恰好在游乐场边界上（y = A·x² + B），所以这一对不计入统计。

**样例 3**

输入：
```

-3 5
-2 3
-1 1
1 0
```
